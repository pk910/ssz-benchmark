# Adapters of other languages

A library of another language is measured through an adapter: a program
that loads the payload, defines the harness types in that language,
verifies them, and runs the operations with the kit's policy, speaking the
protocol of `benchwrap` (`harness/benchwrap/main.go`, the reference of
the messages). The runner builds it with the adapter's `build.sh` and runs
it through the wrapper, which owns the hardware counters and prints the Go
benchmark lines the runner parses. `ethereumssz/` (Rust) is the reference
adapter: copy its structure.

## Layout of an adapter

```
baselines/<adapter>/
  build.sh          build.sh <commit> <out>: toolchain, fetch, generate, build, launchers
  src/...           the benchmark driver and the protocol client
  src/gen_*.*       the type definitions, generated by convert_foreign.py (checked in)
  work/             checkouts the build fetches (not checked in)
```

`build.sh` runs in a copy of the harness as the sandbox user, with network
access, in the adapter's directory. Its environment:

| variable | meaning |
|---|---|
| `BENCH_TOOLCHAINS` | where toolchains live; `source ../../toolchains/<lang>.sh` installs or updates the pinned one and puts it on PATH (idempotent, shared by every build) |
| `BENCH_SEEDS` | the layout seeds, comma separated; a build that can shuffle the layout leaves `out/<fork>-<seed>` per seed, every build leaves `out/<fork>` |
| `BENCH_JOBS` | parallelism for the build |
| `REAL_DATA` | the payload directory when set (the converter reads the spec files from it; default `/srv/benchd/res/real`) |

The launcher `out/<fork>` (and `out/<fork>-<seed>`) is an executable or a
script that runs the adapter for that fork with the arguments appended by
the wrapper.

## What the adapter does

1. Opens the control pipe on file descriptor 3 and names its measuring
   thread (`thread <tid>`, the tid from `gettid` or `/proc/thread-self`);
   the wrapper opens the counters on it and pins it to the benchmark cpu.
2. Reads `BENCH_PATTERN` (Go testing semantics: the pattern split at `/`,
   each element a regular expression against the element of
   `BenchmarkReal/<Engine>/<Object>/<Op>` at the same position; missing
   trailing elements match everything), `BENCH_ITERS` (`Op=N,Op=N`, the
   fixed count per operation) and `BENCH_TIME` (`Nx` iterations, or a
   duration to calibrate against: grow the count 1, 2, 5, 10, ... until a
   batch reaches it and report the count).
3. For each object the pattern selects: loads `REAL_DATA/<fork>[/minimal]/
   {spec.json, <name>.ssz, <name>.root}` (or `blocks/*.ssz` with their
   roots for a set), decodes, re-encodes and compares with the input, hashes
   and compares with the stored root. A difference is `fail <leaf>
   <message>` for every operation of the object (the run then fails at the
   end, as the kit's does), an operation the library lacks is `skip <leaf>`.
4. Measures each operation: untimed warm-up calls (one, two when the
   operation allocates; a JIT runtime warms up until it has settled and
   reports `warmup=<k>`), then `begin <leaf>`, the iterations, `end <leaf>
   iters=<n> ns=<elapsed> bytes=<B> allocs=<N> warmup=<k>` with the bytes
   and allocations summed over the iterations (leave them out when the
   runtime cannot count them). Freeing and collecting is not part of an
   operation: drop or collect the results of a batch between batches
   inside `pause` / `resume`, a batch being as many iterations as keep
   under 256 MB of garbage (the kit's rule).
5. Writes nothing to stdout that is not for the wrapper (stdout and
   stderr of the adapter both land in the job's raw log; the result lines
   are the wrapper's).

## Objects, operations, engines

Objects of the `fulu` launcher: `FuluState`, `FuluBlock`, `FuluBlocks`
(the set: one iteration runs the operation on all 32 blocks), `FuluMinState`,
`FuluMinBlock` (the minimal preset, under `fulu/minimal/`, with its own
`spec.json`). Of `gloas`: `GloasState`, `GloasBlock`, `GloasBlocks`,
`GloasEnvelope`, `GloasMinState`, `GloasMinBlock`. Roots: a state's own,
a signed block's `Message`, an envelope's `Message`.

Operations: `Unmarshal` (bytes to a fresh object), `SizeSSZ`, `Marshal`
(to a new buffer), `MarshalTo` (into a buffer kept across iterations, when
the library has such a call), `HashTreeRoot`. For a tree-backed library
whose roots are cached, HashTreeRoot hashes an object with no cache (a
fresh decode per iteration counts as part of it and is named as such on
the pages), or the structural representation when there is one.

Engine names are fixed per library (one more per representation):
`EthereumSSZ`, `Grandine`, `Teku`, `LodestarValue`, `LodestarTree`,
`Nimbus`, `SszPP`. An object the library cannot express is left out of
the launcher's leaves (no message).

## Types

Generated from `types/<fork>/types.go` by `convert_foreign.py <dialect>`
with the spec files of both presets, one module per preset, so that
the mainnet and the minimal objects use types with the preset's sizes and
limits. A dialect is a module `convert_<dialect>.py` next to it with
`emit(aliases, structs, order, keep, presets) -> str`, built on `shape()`
(the SSZ shape of a field: levels of vector/list/progressive list over a
base of uint/bool/bytes/struct/bitvector/bitlist/progressive bitlist/u256).
A struct with `ssz-index` fields is a progressive container. The
generated files are checked in and regenerated by `build.sh`.

## Verification before a library goes in

Locally: build the wrapper and the adapter, then

```
REAL_DATA=<payload> benchwrap -adapter out/<fork> -test.run '^$' -test.bench . -test.benchtime 1x
```

must print one line per leaf of every object, with no `--- FAIL` line and
exit code 0; the roots then agree with dynamic-ssz's on every object,
progressive lists and the minimal preset included. Then a run with fixed
counts (`BENCH_ITERS=Unmarshal=20,Marshal=40,HashTreeRoot=4`) for the
figures.
